# Dev Log — 2026-03-16

## Summary

Added a Verovio engraving engine to the Qt desktop app as a swappable alternative to the MuseScore engine. Built the full play-along game mode on top of it including note highlighting, tracking cursor, auto-scroll, tie detection, and multi-voice support.

---

## 1. ScoreEngine Abstraction Layer

Created `src/engine/ScoreEngine.h` — abstract interface for swappable engines:
- `loadMusicXML()`, `layout()`, `pageCount()`, `pageSize()`, `renderPage()`
- `partCount()`, `partInfo()`, `setPartVisible()`
- `resolveCursorRect()`, `measureCount()`, `spatium()`
- `usesWebRendering()`, `renderAllPagesHtml()` — for engines that need a web view

Created `src/engine/MuseScoreEngine.h/cpp` — wraps the existing MuseScore 4 code. Exposes `score()` and `renderer()` for legacy features (SyncMode, PlayAlongSynth).

Created `src/engine/VerovioEngine.h/cpp` — Verovio implementation using `vrv::Toolkit`.

## 2. Verovio Integration

- Added Verovio as git submodule at `thirdparty/verovio/`
- Always compiled (no CMake option needed)
- `--verovio` CLI flag selects the engine at runtime
- Bumped C++ standard to C++20 (required by Verovio's Tunings library)
- Verovio `add_subdirectory` placed before global `include_directories` to avoid name clashes (both projects have `src/app.cpp`)

## 3. Rendering via QWebEngineView

QSvgRenderer (SVG Tiny 1.2) couldn't handle Verovio's complex SVG with embedded fonts and nested `<svg>` elements. Switched to QWebEngineView — same approach as the official verovio-qt-demo.

- `VerovioEngine::renderAllPagesHtml()` generates full HTML with all SVG pages
- HTML written to temp file, loaded via `file://` URL
- Web view overlaid on ScoreWidget, `setFocusPolicy(Qt::NoFocus)` to prevent keyboard stealing
- SVG `overflow="visible"` replaced with `overflow="hidden"` (from electron branch)

## 4. Layout Configuration

- `setPageWidthDirect(3200)` — controls measures per system (bypasses circular DPI calculation)
- `scale=40`, `adjustPageHeight=true`, `pageHeight=60000` (continuous vertical scroll)
- `breaks="auto"`, `header/footer="none"`
- CSS `width: 100%` on SVGs scales to viewport

## 5. Part Filtering (MusicXML)

- `filterMusicXML()` rewrites MusicXML to keep only selected parts in requested order
- Removes all `<part-group>` elements, adds bracket group for multi-part levels
- `selectParts(partNumbers)` — stores `m_selectedParts` for later use (tie detection, etc.)
- Matches electron branch: `<part-list>` cleared and rebuilt, `<part>` elements reordered

## 6. Play-Along: Note Table from Verovio

- `getNotesForPart(partIndex, renderedSvgs)` — extracts note element IDs from pre-rendered SVGs
- Uses `GetMIDIValuesForElement()` for pitch, time, duration
- SVGs rendered ONCE in `renderAllPagesHtml()`, cached in `m_renderedSvgs`, reused for note extraction (avoids ID regeneration)
- `RenderToMIDI()` called AFTER `RenderToSVG()` so IDs match
- `PlayAlongSynth::setVoiceFromNotes()` / `addVoiceFromNotes()` — populate voice from external note table
- `PlayAlongSynth::nextNoteIndex()` — exposes current position for highlight mapping

## 7. Tie Detection

Failed approaches: `GetElementAttr` (no `@tie` attribute), SVG `<tie>` elements (no startid/endid), MIDI time heuristic (false positives), MusicXML index matching (count mismatch 345 vs 505).

Working solution: Parse original MusicXML for `<tie type="stop"/>` notes, compute their MIDI time + pitch, match to SVG notes by `(midiTime, pitch)`. Required `m_selectedParts` to map filtered partIndex to original part. Documented in `docs/tie-detection-algorithm.md`.

## 8. Note Highlighting

### Phase 1: JS-based (SVG rect insertion)
- `highlightNotes()` / `clearHighlights()` JS functions
- CSS classes `hl-v0` (blue) / `hl-v1` (violet)
- Rounded rect with padding, inserted before the note element in the DOM

### Phase 2: QPainter overlay (current)
- `WebScoreOverlay` transparent QWidget on top of QWebEngineView
- Position cache fetched once from JS after page load (`fetchNotePositions()`)
- Highlight updates synchronous with keypress — no IPC latency
- JS highlights made invisible (`opacity:0`) but kept in DOM for auto-scroll detection
- 50ms polling timer syncs `scrollY` for manual scroll
- Colors match MuseScore exactly: `QColor(50,120,255,40)` and `QColor(180,80,220,40)`
- Documented in `docs/qpainter-highlight-overlay.md`

## 9. Tracking Cursor

- Blue semi-transparent vertical line spanning full system height
- Timemap built from SVG note elements (not `RenderToTimemap()` — IDs don't match)
- Binary search + linear interpolation between surrounding notes (like MuseScore)
- System height cached once at page load (prevents jitter from highlight rects)
- 80ms forward compensation for web view IPC latency
- Cross-system transitions: first half interpolates to right edge, second half starts at first `.note, .rest` element and interpolates to first note
- Connected to tracking button, seek slider
- Documented in `docs/tracking-cursor-algorithm.md`

## 10. Auto-Scroll

Many iterations. Final algorithm: voice 0 only, scroll when system goes below viewport, system-level snap. Documented in `docs/autoscroll-algorithm.md`.

## 11. Multi-Voice Support

- Key zones: left keyboard = voice 1, right keyboard = voice 0 (matching electron branch)
- Per-voice note tables, soundfonts, GM programs
- Per-voice QPainter highlights (blue + violet)
- Instrument panel populated with per-voice soundfont/instrument combos

## 12. Video/UI Management

- `--screen N` CLI flag to open on specific monitor
- Video auto-expands when entering a level, collapses to sidebar when navigating
- Resume re-expands video
- Video height fixed at 394px
- `loadYouTube()` skips reload if same URL (just seeks)
- Video paused on level load, resized on `videoReady`
- Per-interpretation tuning, volume, and beats applied on load and switch

## 13. FluidSynth Fixes

- `init()` made idempotent (prevents double synth creation, stale soundfont IDs)
- `clearVoices()` stops notes without `program_reset` (was wiping channel programs)
- `setVoiceFromNotes()` uses `program_select` with soundfont ID (not `program_change`)
- Full play-along reset at start of every `loadLevel`

## 14. Bug Fixes

- SyncTimer `setTime()` guard: checks `m_engine` in addition to `m_score` (Verovio mode has null `m_score`)
- QPainter save/restore balance in MuseScoreEngine::renderPage
- Score owned by MuseScoreEngine, not double-deleted by App
- Instrument combos populated for Verovio voice setup
- `sources.json` reordered: Jordi Savall first
