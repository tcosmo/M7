# Tracking Cursor Algorithm (Verovio Engine)

## Overview

A semi-transparent blue vertical line tracks the playback position across the score, interpolating smoothly between note positions within each system. It matches the MuseScore desktop cursor behavior.

## Data Flow

```
YouTube player → positionChanged(seconds)
    ↓
App::onPositionChanged(seconds)
    ↓ adjusts for interpretation start offset
SyncTimer::setTime(adjusted)
    ↓ binary search in beatTimes, interpolates to tick
    ↓ stores m_lastTick
App reads m_syncTimer->currentTick()
    ↓ adds 80ms forward compensation for web view IPC latency
ScoreWidget::setCursorTick(tick)
    ↓ runJavaScript("setCursorTick(tick)")
JS: setCursorTick(tick)
    ↓ binary search in timemap, interpolates x between elements
    ↓ positions blue div at interpolated x, spanning system height
```

## Building the Timemap

### Problem: ID mismatch

Verovio's `RenderToTimemap()` returns MEI internal element IDs which are **different** from the SVG element IDs generated by `RenderToSVG()`. They are independently generated random IDs that don't match.

### Solution: build timemap from SVG notes

In `renderAllPagesHtml()`, after rendering all SVG pages:

1. Parse each rendered SVG for `<g class="note">` elements
2. For each note, get its SVG element ID
3. Call `GetMIDIValuesForElement(id)` to get its MIDI onset time
4. Store `{qstamp, elementId}` where `qstamp = midiTime / 500.0` (Verovio uses 500 MIDI ticks per quarter note)
5. Sort by qstamp

This guarantees the timemap IDs match the SVG DOM exactly.

### Tick conversion

- **Verovio MIDI**: 500 ticks per quarter note
- **SyncTimer/MuseScore**: 480 ticks per quarter note
- **Conversion**: `qstamp = verovioTick / 500.0`, then `musescoreTick = qstamp * 480`
- `timemapAsJs()` outputs ticks as `qstamp * 480` for the JS side

## SyncTimer: Time → Tick

The SyncTimer receives playback time in seconds and interpolates to a tick position using beat data from `beatdata.json`:

1. Binary search `beatTimes` to find surrounding beats
2. Linear interpolation: `t = (seconds - prevBeatTime) / (nextBeatTime - prevBeatTime)`
3. `interpTick = prevBeatTick + t * (nextBeatTick - prevBeatTick)`

Beat ticks are computed as `beatIndex * 480` (480 per quarter note).

### Guard condition

`setTime()` requires either `m_score` (MuseScore) or `m_engine` (Verovio) to be non-null. In Verovio mode, `m_score` is null, so `m_engine` must be set via `setEngine()`.

## JavaScript: Tick → Cursor Position

### `setCursorTick(tick)` algorithm

1. **Binary search** the timemap for surrounding entries `lo` and `hi`
2. **Find SVG elements** via `document.getElementById(timemap[lo].id)` and `timemap[hi].id`
3. **Get x positions** via `getBoundingClientRect()` (live DOM queries — simple, always correct)
4. **Interpolate x** between the two elements if they're in the same system:
   ```
   t = (tick - lo.tick) / (hi.tick - lo.tick)
   x = x1 + (x2 - x1) * t
   ```
   If elements are in different systems, snap to `x1` (no cross-system interpolation)
5. **Position cursor div** at interpolated x, spanning full system height from `system.getBoundingClientRect()`

### Cursor div

- `position: absolute` (moves with document scroll)
- `background: rgba(50, 100, 255, 0.35)` (semi-transparent blue, matching MuseScore)
- `width: 4px`
- `height: system.height`
- `z-index: 999` (above score content)

### Rest handling

Entries with empty element IDs (rests) are filtered out of the timemap at build time. During a rest, the binary search lands on the last note before the rest, and the cursor stays at that position.

## Latency Compensation

The web view IPC (Qt → Chromium) adds ~50-80ms latency. To compensate, the cursor tick is computed at `adjusted + 0.08` seconds, then the SyncTimer is restored to the actual position:

```cpp
m_syncTimer->setTime(adjusted + 0.08);
m_scoreWidget->setCursorTick(m_syncTimer->currentTick());
m_syncTimer->setTime(adjusted); // restore
```

## Comparison with MuseScore Cursor

| Aspect | MuseScore | Verovio |
|--------|-----------|---------|
| Rendering | QPainter in paintEvent (synchronous) | HTML div via JS (async IPC) |
| X interpolation | Between score segments in measure | Between timemap entries (SVG note elements) |
| Y span | System staff bounds from Score DOM | System `getBoundingClientRect()` |
| Latency | None (same paint event) | ~80ms (compensated) |
| Position source | Score segment canvas positions | SVG element bounding rects |
| Color | `QColor(50, 100, 255, 120)` | `rgba(50, 100, 255, 0.35)` |
