## 5. YouTube Video UX — Simplified Architecture

After extensive debugging of auto-play, reparenting, resize flash, and state sync issues,
the video lifecycle was drastically simplified to a create-per-level / destroy-on-exit model.

### Architecture
- **Navigation has NO video** — no player exists, no sidebar video, no audio
- **Each level creates a fresh YouTube player** via `loadYouTube()` → placed directly in `m_expandedVideoContainer`
- **Exiting a level destroys the player entirely** — stop, pause, remove view, deleteLater, delete player
- **No reparenting** — the QWebEngineView is never moved between containers
- **No sidebar video** — removed sidebar video container, expand/collapse button, volume slider at startup
- **No Resume** — every level click is a fresh `loadLevel` creating a new player
- **No same-URL reuse** — always destroy and recreate

### Destruction Sequence (used everywhere: showWorldBrowser, world card click, loadLevel)
```cpp
m_youtubePlayer->stop();
m_youtubePlayer->pause();
auto* view = m_youtubePlayer->videoWidget();
if (view) { view->setParent(nullptr); view->deleteLater(); }
delete m_youtubePlayer;
m_youtubePlayer = nullptr;
```

### Playback
- `m_needsSeekOnPlay = true` set in `loadLevel()` — video sits untouched until user presses Play
- `playerPlay()` is the ONLY place that seeks to `m_interpStart` and calls play
- All keyboard events blocked in navigation view

### What Was Removed
- Sidebar video (`setVideoWidget`, video container in WorldSidebar)
- Expand/Collapse button (`m_videoExpandButton`, `toggleVideoExpand()`)
- Sidebar interpretation combo
- Volume slider at startup
- Same-URL early return in `loadYouTube()`
- Resume functionality
- Auto-load of first interpretation at startup

### Other Fixes
- Keyboard isolation: QWebEngineView + child widgets set to Qt::NoFocus
- `--no-proxy-server` Chromium flag to suppress WPAD errors
